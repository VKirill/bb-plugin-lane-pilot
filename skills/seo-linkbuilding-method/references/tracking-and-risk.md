# Four-registry tracking and risk policy — reference

Source: «SEO Монстр 2027» ch6 pp. 538–557, 549–560.

## Four registries (pp. 549, 553–555)

1. **Platforms & Contacts** — domain, rubric, language, decision-maker, contact, author-profile support, terms, status.
2. **Campaigns** — campaign card (8 fields) per campaign: goal, cluster, acceptors, donor types, budget, timeline, owner, success metric.
3. **Materials & Acceptors** — permanent ID per asset and acceptor.
4. **Publications & Links** — per link three URLs: exact href, final URL after redirects, intended acceptor. Keep parameters until their role is known.

Two state axes, never merged:

- Workflow: Found → Verified → Pitch Prepared → Sent → Reply → Approved → Published (+ stop reason).
- Link state: Confirmed, Content Changed, Acceptor Changed, Missing, Page Unavailable, Manual Check.

Five separate dates: publication; link added; first internal check; tool discovery; change. Unknown publication date stays "unknown" — never use the import date.

Contact log (7 fields) shared across departments — no independent duplicate pitches to one publisher. Costs tracked in full (7 components); paid/sponsored placements kept separate and never budgeted as ranking.

## Reporting — five metric levels (pp. 555–557)

Preparation → communication → publications → visits → search. Mark "attribution not established" where the link to results is unproven. A repeat publication or restored link is not a new domain — count restorations separately. Cost per placement compares process effort, not ranking value. Editorial links need no UTM; on-site moves use analytics events, never internal UTMs. Periodic snapshots; retention compared only across cohorts observed the same length of time.

## AI hygiene (p. 557)

LLM flags, as a review queue only: missing fields, name variants, duplicates, tasks without a next action, acceptor mismatches, term/status conflicts. The AI never deletes rows or changes statuses. Confirm link state with an HTTP checker. Human reviews flagged anomalies and Manual Check rows.

Small sites start with spreadsheet + GSC + analytics; paid tools only when needed. Before any new method: write down what is being tested and the conditions for continuing.

Roles: owner, SEO, subject expert, editor, communications, analyst — plus a backup expert with a deadline.

## Profile risk audit (pp. 538–540)

- ~80% of links explainable only as exchange purchases → high Core Update risk.
- 80–90% of links on the homepage → structural defect; redirect acquisition to clusters.
- Footer link ≠ spam by default: judge purpose, template spread, hidden links, widget type.
- Donor redirect target changed → judge relevance by saved original href + redirect chain.
- Spike attribution: count pages, domains, independent organizations, mention reasons; separate sitewide/syndication waves from editorial; separate tool discovery date from publication date; check timing vs internal events; flag same-brief article clusters.
- Pre-campaign 5-dimension risk check: search, financial, reputational, technical, operational.
- Placement governance record per placement: who approved, on what terms, exact target URL, expected outcome.

## Vendor and expired-domain vetting (pp. 541–545)

Require before payment: breakdown of work types, platform criteria, placement terms. Independently sample the vendor's full archive across ages, types, topics and formats, including edited or removed items — check what happened to old ones. Confirm with the media's editorial office (contacts found yourself) that it works with the intermediary; ask about format, approvals, policy on titles, anchors, rel. Split fee: research, writing, outreach, ad fee, technical checks, monitoring. Sign acceptance criteria per placement.

Placement acceptance criteria (10): domain and section; format; topic; exact acceptor; allowed anchors; rel attributes; duration; error SLA; removal protocol; no swaps without approval.

Media intermediary authorization (5 checks); publisher network transparency (6); expired domain check (6): business reason, content inventory, rights, original linked pages, preserved intent, delivered document. Seller-promise questions (7).

Reject: bulk-by-quantity packages; cannot explain platforms pre-payment; networks selling hidden ownership or refusing verification; three-way exchanges; mass AI article variants; "dofollow"/"eternal link" as criteria; expired domains bought only to redirect metrics; CMS/GSC access requests just to place links (deny, or minimal access for a fixed time). Hidden platform lists are not necessarily deception — but you may refuse a blind risk.

## Disavow and manual actions (pp. 543, 545, 547–548)

1. Check GSC Manual Actions for an official penalty; read exact wording.
2. Demand justification: disputed links, how created, evidence of site involvement, risk per group, which links you control.
3. Remove or rel-attribute controllable violating links; stop new orders under any spam scheme.
4. Disavow **only** when both hold: large volume of artificial links AND an active manual action or well-founded risk of one.
5. Back up the current disavow file — upload replaces it entirely. Review the new list, upload, file reconsideration if an action exists.

A third-party toxicity score is not a Google notice — do not mass-disavow or pay for removals. Hack, security issue or manual action → freeze link expansion and budget increases. The upload itself is irreversible — owner approves.

## Review cadence (pp. 551–552, 554, 560)

- Weekly: replies, new publications, overdue approvals, undated next steps, new mentions.
- Monthly: cost vs results; rejection reasons; key live placements; lost links; asset queue; four questions — what got published, what went unclaimed, what needs fixing, which single task continues.
- Quarterly: business priorities; expert availability; evergreen freshness; single-contractor/publisher dependence.
- Per-campaign decision each review: continue / change pitch / rework asset / repair placement / reallocate.
- Many pitches, no replies → fix targeting and offer, not volume. Interest, no publication → missing evidence/permissions, unsuitable acceptor, or internal delays.
- Treating activity metrics as outcomes is the main anti-pattern.

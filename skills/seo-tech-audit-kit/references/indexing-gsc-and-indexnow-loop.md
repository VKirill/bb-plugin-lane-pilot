## 1. Архитектура контура доставки и измерения (`Discovery → Indexation → Ranking → Conversion`)

Главное правило операционного учёта в Programmatic SEO — **никогда не смешивать пять разных состояний URL**:

| № | Состояние URL | Что реально произошло | Источник правды (чем проверять) | Типичная ошибка интерпретации |
| :--- | :--- | :--- | :--- | :--- |
| 1 | **`Published (Live)`** | Страница задеплоена на продакшен, отдаёт `HTTP 200`, включена в `sitemap.xml` и перелинкована | Прямой HTTP-запрос + автоматический route-check | Считать, что опубликованная страница уже видна в поиске |
| 2 | **`Discovered`** | Поисковик узнал о существовании URL (через sitemap, внутреннюю ссылку или `IndexNow`), но ещё не обошёл его | GSC / Bing URL Inspection (`Discovered - currently not indexed`), ответ `200 OK` от IndexNow | Паниковать и создавать дубликат страницы вместо усиления внутренних ссылок и ожидания обхода |
| 3 | **`Indexed`** | Краулер скачал страницу, прошёл фильтр качества и допустил её в поисковый индекс | Живой **URL Inspection** (`URL is on Google`), фильтр `Indexed pages` | Доверять только сводному графику индексации GSC, который отстаёт от живого URL Inspection на несколько дней |
| 4 | **`Ranking`** | Страница начала получать реальные показы (`Impressions`) и позиции по поисковым запросам | **GSC Performance** (фактическая правда) + **Ahrefs Rank Tracker** (контрольный срез по гео) | Принимать расчётный `Ahrefs Traffic` за реальные визиты или делать выводы по запросу с 1 показом |
| 5 | **`Converting`** | Посетитель из органического поиска совершил целевое действие (загрузил экспорт, начал триал, оплатил) | Серверная аналитика / БД продукта / CRM / GA4 | Оценивать успех SEO только по росту позиций без привязки к регистрациям (`organic signups`) |

## 2. Протокол мгновенного уведомления `IndexNow` и интеграция с Bing Webmaster Tools

Молодой сайт с низким авторитетом роботы обходят редко: без активного сигнала новая BOFU-страница или обновлённая таблица цен может ждать обхода неделями.

### 2.1. Роль связки `Sitemap + IndexNow + Bing + GSC`
Эти инструменты **не заменяют**, а дополняют друг друга:
- `Internal Links` — дороги внутри сайта, передающие контекст и приоритет;
- `sitemap.xml` — полная актуальная карта всех канонических индексируемых URL;
- `IndexNow` — мгновенное push-уведомление об изменениях для Bing, Яндекса и партнёрских индексов (критично также для попадания свежих страниц в ответы **ChatGPT** и AI-поиска);
- `GSC URL Inspection & Priority Crawl Queue` — прямая подача приоритетных URL в очередь обхода Google (в пределах дневного лимита).

### 2.2. Спецификация настройки и отправки `IndexNow`
1. **Публичный ключ верификации хоста:**
   Сгенерируйте ключ (например, `PUBLIC_KEY`) и разместите текстовый файл `https://example.com/PUBLIC_KEY.txt`, внутри которого записана ровно эта строка. *(Это не секретный API-токен, а публичное доказательство владения доменом).*
2. **Структура POST-запроса:**
   ```json
   {
     "host": "invoisin.com",
     "key": "PUBLIC_KEY",
     "keyLocation": "https://invoisin.com/PUBLIC_KEY.txt",
     "urlList": [
       "https://invoisin.com/vs/harvest",
       "https://invoisin.com/harvest-pricing",
       "https://invoisin.com/import-from-harvest"
     ]
   }
   ```
3. **Когда отправлять `IndexNow`:**
   - Сразу после публикации новой партии канонических страниц;
   - После содержательного обновления страницы (смена тарифов конкурента в таблице, добавление нового интерактивного модуля);
   - После установки 301 редиректа или удаления страницы.
   - *Запрещено:* отправлять неизменённые URL по крону каждый час — это не ускоряет ранжирование и приводит к блокировке по rate-limit.

### 2.3. Девять инженерных требований к безопасному `Post-Deploy Hook` для IndexNow
Автоматическая задача (Rake task / GitHub Action / Kamal post-deploy hook) обязана соблюдать следующие правила (на примере guarded-таска `invoisin.com` на 43 канонических URL):
1. **Production-only Guard:** запускаться строго при `RAILS_ENV=production` / `NODE_ENV=production` (никогда со staging или localhost).
2. **Host & HTTPS Validation:** проверять, что все URL начинаются с канонического `https://<production_host>`.
3. **Minimum URL Count Threshold:** проверять, что в `sitemap.xml` присутствует не меньше минимально ожидаемого числа URL (например, `>= 25`), чтобы при сбое генератора сайтмапа не отправить пустой список.
4. **Live Key Verification:** перед отправкой делать GET-запрос к `keyLocation` и сверять совпадение ключа.
5. **Deduplication:** удалять дублирующиеся URL из массива `urlList`.
6. **Noindex Exclusion:** жёстко отфильтровывать служебные маршруты (`/signin`, `/signup`, `/admin`, `/profile`).
7. **Dry-Run Support:** поддерживать флаг `--dry-run`, который выводит `host`, `keyLocation` и точный список URL в консоль без сетевой отправки.
8. **Release Logging:** записывать дату, количество отправленных URL и HTTP-статус ответа в `seo/RELEASE_LOG.md`.
9. **Non-Blocking Failure Handling:** временная ошибка сети или таймаут сервера IndexNow **не должны валить продакшен-деплой приложения**; ошибка логируется, а отправку можно безопасно повторить вручную (`manual retry`).

### 2.4. Использование Bing Webmaster Tools как второго контура диагностики
- **Site Scan:** запускать после каждого крупного релиза для независимой проверки технических ошибок (в `invoisin.com` первый скан нашёл 2 слишком длинных `<title>`, после исправления повторный скан прошёл **40 URL с 0 errors и 0 warnings**).
- **Bing Keyword Research:** использовать для поиска недооценённых утилитарных запросов (именно через Bing в `invoisin.com` нашли кластер `time card calculator / work hours calculator / time sheet calculator` под `/calculators/timesheet`).

## 3. Контур обратной связи: Google Search Console + Ahrefs Rank Tracker

### 3.1. Правила чтения данных и защита от ложных выводов
1. **Разделение ролей:**
   - `Ahrefs` оценивает внешний рынок, конкурентов и снимает регулярные срезы позиций по выбранным локациям (`US`, `GB`);
   - `GSC` показывает фактические показы и клики реальных людей в Google;
   - `Product DB / Analytics` подтверждает регистрации и оплаты.
2. **Учёт лагов и порогов приватности:**
   - Сводный отчёт индексации GSC отстаёт на 2–5 дней — для приоритетных страниц используйте прямой `URL Inspection`.
   - GSC скрывает часть сверхнизкочастотных запросов из таблицы по порогу приватности (`privacy threshold`), поэтому сумма показов по строкам запросов может быть меньше общего числа показов страницы.
   - В `Ahrefs Rank Tracker` позиции обновляются в конкретный момент времени (например, 31 августа, тогда как новые статьи вышли 1 сентября) — всегда сверяйте колонку `Updated` с датой деплоя.
   - **Целевой ориентир CTR:** на рабочей сетке программных страниц средний CTR в GSC не должен опускаться **ниже 0,7%**; падение ниже этого порога при хорошей позиции сигнализирует о несовпадении Title/сниппета с интентом или перехвате кликов блоками SERP features.

### 3.2. Шесть позиционных сегментов и матрица действий

По результатам еженедельного среза все отслеживаемые пары `ключ × страна` (в `invoisin.com` — **141 ready-ключ × 2 страны = 282 канонические пары**) разбиваются на 6 операционных корзин:

| Корзина (Сегмент) | Диапазон позиций | Диагноз | Каноническое действие на итерацию |
| :--- | :--- | :--- | :--- |
| **1. Winner** | **1 – 3** | Страница выиграла ТОП-3 (`harvest vs tsheets` — поз. 1 US, поз. 3 GB) | Удерживать свежесть фактов (`checked_at`), тестировать улучшение CTR сниппета и конверсию первого экрана / интерактивного модуля в signup |
| **2. Page 1** | **4 – 10** | На первой странице, но не собирает максимум кликов (`harvest invoice import` — поз. 7 GB, поз. 9 US) | Укрепить блок доказательств (`proof`), добавить свежие датированные источники, усилить входящие внутренние анкоры со спиц кластера |
| **3. Striking Distance** | **11 – 20** | В шаге от первой страницы (`harvest vs quickbooks time` поз. 12 US, `freshbooks vs harvest` поз. 20 US) | **Приоритет №1 для правок!** Сравнить структуру, `Title/H1` и `unique_module` с текущим ТОП-10; добавить недостающий раздел или интерактивный блок. *Запрещено плодить новые страницы в кластере, пока не доработан Striking Distance!* |
| **4. Emerging** | **21 – 50** | Поисковик понял тему, но считает страницу слабее конкурентов (`harvest competitors` поз. 26 US) | Расширить полноту ответа, добавить таблицу решений/калькулятор и связать двусторонними ссылками с другими страницами семейства |
| **5. Invisible** | **> 50 или `no rank`** | Нет видимости | Проверить цепочку: `Indexed?` → `Соответствует ли страница SERP-intent?` → `Хватает ли авторитета домена (DR) для данного KD?` |
| **6. Wrong Page** | **Любая позиция** | Ранжируется не тот URL, который назначен в `keyword-map.csv` (`harvest to invoisin` → `/vs/toggl-vs-harvest`) | Запустить `Ownership Audit`: перенаправить внутренние анкоры на канонического владельца, развести `Title/H1` или склеить дубли 301 редиректом |

### 3.3. Диагностическая таблица перекрёстной сверки (`Rank Tracker × GSC × Signups`)
```text
Rank ↑  +  GSC Impressions ↑  +  Organic Signups ↑   ===>  Масштабировать кластер (выпускать следующие спицы)
Rank ↑  +  GSC Impressions ↑  +  Organic Signups = 0 ===>  Проблема соответствия интенту или оторванный от задачи CTA
Rank ↓  +  GSC Impressions/Clicks стабильны          ===>  Временная волатильность трекера — НЕ переписывать страницу!
GSC / Tracker показывает неверный целевой URL         ===>  Каннибализация — чинить внутренние ссылки и Title/H1 по карте владения
0 Impressions через 14+ дней после деплоя            ===>  Проверить URL Inspection (индексацию), реальный спрос и KD
```

## 4. Протокол одиночной итерации (`One-Change Iteration`) и Weekly SEO Review

Самая частая ошибка после запуска — при первом колебании позиции одновременно переписать `Title`, `H1`, весь текст, поменять CTA и перекроить внутренние ссылки. В результате невозможно понять, какая именно правка помогла или навредила.

### 4.1. Правило одной переменной и шаблон карточки эксперимента (`seo/experiments/`)
На одной странице за одну итерацию меняется **ровно одна осмысленная переменная** (или одна тесно связанная пара, например `Title + Meta Description` для роста CTR), после чего выдерживается окно наблюдения **14–28 дней**.

```yaml
# Карточка SEO-эксперимента (seo/experiments/2026-08-01-harvest-import-snippet.yaml)
date_started: "2026-08-01"
canonical_path: "/harvest-import"
target_query: "how to migrate from harvest"
signal_source: "GSC"
baseline_signal: "Impressions растут (+158%), средняя позиция 12–15, но низкий CTR сниппета"
hypothesis: "Текущий Title выглядит как общая статья, а не как пошаговая инструкция с превью импорта без потери истории"
single_change: "Переписать только <title> и <meta name='description'> с акцентом на пошаговый перенос клиентов, таймшитов и инвойсов"
expected_result: "Рост CTR в GSC без потери позиции по основному кластеру"
observation_window_days: 21
actual_result: "" # заполняется через 14-28 дней
decision: "pending" # keep | revert | iterate
```

### 4.2. Регламент еженедельного 45-минутного ревью (`Weekly SEO Review`)
Проводится строго раз в неделю по 8 пунктам:
1. Сверка доли проиндексированных страниц (`Indexed URLs / Sitemap URLs`);
2. Динамика `Clicks / Impressions / CTR / Avg Position` в GSC за 7 и 28 дней;
3. Появившиеся новые запросы (`New queries`), по которым сайт начал получать показы;
4. Разбор корзины `Striking Distance` (позиции 4–20);
5. Проверка ошибок владения (`Wrong landing pages`) и каннибализации;
6. Страницы, теряющие показы (`Pages losing impressions` — проверка свежести фактов и тех. доступности);
7. Сверка органических регистраций, триалов и оплат (`Organic signups & revenue`);
8. Утверждение **максимум 5 конкретных проверяемых задач** на следующую неделю.

## 5. Канонический 30-дневный план запуска кластера (4 недельных спринта + Scorecard)

Этот план позволяет за 30 дней пройти путь от нулевого/сырого состояния до работающего измеримого конвейера без выгорания и без генерации мусора.

### Неделя 1: Технический фундамент и Baseline
- Подтвердить домен в Google Search Console и Bing Webmaster Tools (+ Яндекс Вебмастер для RU).
- Сгенерировать и отправить чистый `/sitemap.xml`.
- Выгрузить все публичные URL и проверить цепочку `HTTP 200 → index,follow → self-canonical`.
- Исключить служебные страницы (`/signin`, `/signup`, `/admin`) из `sitemap.xml` и закрыть их `noindex, follow`.
- Исправить все битые внутренние ссылки и длинные/дублирующиеся `Title`.
- Настроить трекинг целевого события конверсии (`organic_signup` / `import_preview_started`).
- Зафиксировать полный срез метрик в `seo/BASELINE.md` (с точной датой и периодом).
- **Пропускной Gate Недели 1:** *100% URL в `sitemap.xml` проходят технический аудит с нулём ошибок.*

### Неделя 2: Исследование спроса и Карта владения (`Ownership Map`)
- Собрать 200–1 000 сырых ключей из Ahrefs, Bing Keyword Research, подсказок SERP и вопросов клиентов в неизменяемый `seo/raw-keywords.csv`.
- Разметить для каждой строки `intent`, `business_fit (1..5)` и отсечь `off-ICP` ловушки.
- Сгруппировать запросы по единому `SERP-intent` в первые **10–20 приоритетных кластеров** (фокус на P0 BOFU: `Comparison`, `Alternative`, `Migration`, `Pricing`, `Persona`).
- Назначить каждому кластеру ровно один `canonical_path` в `seo/keyword-map.csv`.
- Разделить статусы `planned` и `ready`, проверить существующие маршруты скриптом и загрузить `ready`-ядро в Rank Tracker по целевым странам (например, US + GB).
- **Пропускной Gate Недели 2:** *Ни для одного SERP-intent нет двух конкурирующих `ready` URL.*

### Неделя 3: Производство первой партии полезных страниц (5–10 URL)
- Заполнить YAML-спецификации (`seo/page-specs/`) для первых **5–10 страниц** одного тематического кластера.
- Собрать проверенные факты продукта (`product_facts`) и датированные официальные источники конкурентов (`fresh_facts`).
- Встроить на страницы уникальные полезные модули (`unique_module`: калькулятор, превью-импортер, интерактивную матрицу решений, редактируемый шаблон).
- Сгенерировать черновики через `bb cf`, провести сверку утверждений (`fact-check`) и вычитку по 9 правилам `Humanizer`.
- Связать все страницы кластера двусторонними контекстными ссылками (`Hub ↔ Spoke`).
- Прогнать автоматический и человеческий QA-гейты и выкатить партию на продакшен.
- **Пропускной Gate Недели 3:** *Каждая выпущенная страница полезна пользователю даже без SEO-текста.*

### Неделя 4: Доставка в индекс, авторитет сущности и первый цикл измерений
- Проверить обновлённый продакшен `/sitemap.xml`, запустить `Bing Site Scan` и `isitagentready.com`.
- Отправить новые URL через guarded post-deploy хук `IndexNow` и запросить приоритетный обход ключевых страниц через `GSC URL Inspection`.
- Оформить по единому `Listing Kit` карточки продукта на P0-площадках (**G2**, **Capterra**) и отправить нейтральные приглашения реальным активным клиентам для сбора первых **5 честных отзывов**.
- Снять первые сигналы из матрицы `GSC page × query` и `Ahrefs Rank Tracker`.
- Зафиксировать первую проверяемую гипотезу (`One-Change Iteration`) и выбрать до 5 решений на следующий 30-дневный цикл.
- **Пропускной Gate Недели 4:** *Каждый `live` URL имеет подтверждённый путь обнаружения поисковиком и назначенного владельца следующей итерации.*

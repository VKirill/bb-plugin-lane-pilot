# Яндекс Директ ЕПК (v501): Архитектура кампаний, комбинаторные объявления и автотаргетинг

> **Целевой скилл**: `mkt-yandex-direct-epk`
> **Назначение**: Производственный справочник по проектированию и программному управлению кампаниями Яндекс Директа на базе Единой перформанс-кампании (`UNIFIED_CAMPAIGN` + `RESPONSIVE_AD`, API `/json/v501/`) через шлюз `ohmy-seo` (`mcp-yandex-seo`), разделению Поиска / РСЯ / Мастера кампаний и управлению категориями автотаргетинга.

---

## 1. Переход на ЕПК (`UNIFIED_CAMPAIGN`, API `/json/v501/`)

В современной архитектуре Яндекс Директа классические форматы (`TEXT_CAMPAIGN`, `TextAd`, `TextImageAd`, смарт-баннеры и графические объявления старого поколения) выведены из эксплуатации в пользу **Единой перформанс-кампании (ЕПК)** на эндпоинте `https://api.direct.yandex.com/json/v501/` (песочница: `https://api-sandbox.direct.yandex.com/json/v501/`).

### Ключевые архитектурные инварианты v501
1. **Единственный рабочий контур перформанс-кампаний**: связка `UNIFIED_CAMPAIGN` (уровень кампании) + `AdGroup` без устаревшего поля `Type` + комбинаторное объявление `RESPONSIVE_AD` (до 3 неархивных объявлений на группу).
2. **Ловушка тихого отказа показа (`Silent No-Serve`)**: отправка `ResponsiveAd` внутрь старой `TEXT_CAMPAIGN` возвращает валидный `Id` без ошибки API, однако такое объявление **никогда не выходит в показы на поиске**. Все новые запуски создаются исключительно в `UNIFIED_CAMPAIGN`.
3. **Строковая типизация `AdId` (`> 2^53`)**: идентификаторы объявлений ЕПК имеют порядок `18574521036675652` и превышают предел `Number.MAX_SAFE_INTEGER` (`9007199254740991`) в IEEE-754 float64. Любой парсинг JSON без сохранения строкового представления округляет младшие разряды и вызывает ошибку `8800` при `Ads.update` / `Ads.moderate`. В БД, JSON-контрактах и вызовах MCP `AdId` передаётся как строка.
4. **Отсутствие идемпотентности у `*.add`**: API Директа не поддерживает `Idempotency-Key`. При сетевом таймауте повторный `add` создаёт дубликат. Обязательный протокол: предварительный `get` по бизнес-ключу `(CampaignId, Name)` и запись выданного `Id` в локальное состояние до возврата ответа.

## 2. Разделение контуров: Поиск vs РСЯ vs Мастер кампаний

Несмотря на то что ЕПК технически позволяет включить смешанный показ, **смешивание Поиска и РСЯ в одной кампании разрушает управляемость ставок, статистику и обучение автостратегии** из-за принципиально разной механики аукциона, CTR и холодной/горячей природы спроса.

| Параметр | ЕПК — Поиск (`Search Only`) | ЕПК — РСЯ (`Network Only`) | Мастер кампаний (МК) / Товарная кампания |
|---|---|---|---|
| **Природа спроса** | Горячий сформированный интент в момент ввода запроса | Холодный / тёплый догоняющий показ по интересам, поведенческому профилю и ретаргетингу | Автоматизированный микс Поиска + РСЯ для быстрого старта или e-commerce фида |
| **Настройка `BiddingStrategy`** | `Search`: активная стратегия; `Network`: строго `SERVING_OFF` | `Search`: строго `SERVING_OFF`; `Network`: активная стратегия | Управляется только в веб-интерфейсе (ограниченная видимость в API) |
| **Роль ключевых фраз** | Точные поисковые запросы + операторы соответствия + жёсткая кросс-минусация |Тематические маркеры интересов и контента площадок (без узких операторов `!`, `"..."`, `[...]`) | Автоподбор по посадочной странице и фиду |
| **Минусация** | Обязательна на старте и еженедельно по `SEARCH_QUERY_PERFORMANCE_REPORT` | Осторожная (минусация в РСЯ отсекает площадки целиком по вхождению слова на странице!) | Только базовые стоп-слова и фильтр площадок |
| **Изображения и видео** | Влияют на расширенные форматы/саджесты, но ядро — заголовок + релевантность | Критический драйвер CTR и фильтрации аудитории (широкоформатные `16:9`, квадратные `1:1`, вертикальные `9:16`) | Обязательный полный пакет ассетов |
| **Чистка трафика** | Поисковые запросы (`Search Terms`) | Площадки показа (`Placement` — исключение мусорных мобильных приложений `dsp.*`, игр, дорвеев, VPN-прокси) | Ручной контроль ограничен |

### Правило одной активной стороны стратегии в ЕПК
В API v501 `UNIFIED_CAMPAIGN` стратегия задаётся **ровно на одной активной стороне** (`Search` или `Network`), тогда как противоположная переводится в `SERVING_OFF` (либо `NETWORK_DEFAULT`, если осознанно требуется единый бюджет).
- Ручная стратегия `HIGHEST_POSITION` допускает пару **только** с `Network: { BiddingStrategyType: "SERVING_OFF" }`.
- Одновременная передача двух независимых автостратегий на `Search` и `Network` отклоняется API.

## 3. Иерархия `Campaign -> AdGroup -> ResponsiveAd` и квоты v501

### 3.1. Уровень кампании (`UNIFIED_CAMPAIGN`)
- Принимает: `Name` (до 255 символов), `StartDate` (`YYYY-MM-DD`, сегодня или будущее), `BiddingStrategy`, `CounterIds` (счётчики Яндекс Метрики), `PriorityGoals` (приоритетные цели с ценностью), `AttributionModel` (`LAST_YANDEX_DIRECT_CLICK`, `LASTSIGN`, `AUTOMATIC`), `NegativeKeywords` (до 20 000 символов без пробелов), `NegativeKeywordSharedSetIds` (до 3 общих наборов по 20 000 символов), `TrackingParams` (шаблон UTM-разметки на уровне кампании).
- **Геотаргетинг (`RegionIds`) не задаётся на уровне кампании** — он живёт исключительно на уровне `AdGroup` (`225` — Россия, `213` — Москва, `1` — Москва и МО, `2` — Санкт-Петербург; справочник `Dictionaries.get{"DictionaryNames": ["GeoRegions"]}`).

### 3.2. Уровень группы (`AdGroups.add` в ЕПК)
- **Не передавать поле `Type` / `TextAdGroup`** при создании группы внутри `UNIFIED_CAMPAIGN` — API v501 возвращает ошибку `8000` (`Unknown parameter`).
- Принимает: `Name` (именуется по **маркерному запросу** кластера с максимальной точной частотностью `«[!фраза]»`), `CampaignId`, `RegionIds`, `NegativeKeywords` (до 4 096 символов), `TrackingParams`.
- Рекомендуемая плотность: `1 кластер интента = 1 группа` (до 200 ключевых фраз на группу; при узком B2B-спросе группировка слишком мелких фраз избегает статуса «Мало показов»).

### 3.3. Комбинаторное объявление (`RESPONSIVE_AD`)
Вместо одиночного `TextAd` в ЕПК создаётся комбинаторный контейнер `ResponsiveAd`, из элементов которого алгоритмы Директа собирают варианты под конкретный запрос и трафарет выдачи.

| Поле `ResponsiveAd` | Лимит количества | Символьный и словарный лимит | Критические ошибки API v501 |
|---|---|---|---|
| `Titles` | `1..7` заголовков | `<= 56` символов (вкл. пробелы и знаки); **каждое отдельное слово `<= 22` символов** | Слово длиннее 22 символов вызывает ошибку `5001` |
| `Texts` | `1..3` текстов | `<= 81` символа (вкл. знаки препинания); **каждое отдельное слово `<= 23` символов** | Составные слова через дефис или латиница `> 23` симв. (например, `профессионально-технический`) валят всё объявление с ошибкой `5001` |
| `Href` | `1` URL (строка) | Полный `https://` адрес с финальным путём без редиректов | Поле единственного числа (`Href`, не `Hrefs`) |
| `DisplayUrlPath` | `0..1` отображаемая ссылка | До `20` латинских или `9` кириллических символов, без `/` и `http` | Кириллица длиннее 9 знаков отклоняется валидатором |
| `AdImageHashes` | `0..5` хэшей картинок | Предварительно загруженные через `AdImages.add` | Передаётся массив хэшей `AdImageHashes` |
| `SitelinkSetId` | `0..1` набор быстрых ссылок | `4..8` быстрых ссылок с описаниями (повышают площадь сниппета в премиум-трафаретах) | Создаётся заранее через `Sitelinks.add` |
| `VCardId` / `BusinessId` | `0..1` визитка / профиль Карт | Привязка к Яндекс Бизнесу даёт рейтинг, отзывы и адрес в сниппете | Повышает CTR на поиске на 10–25% |
| **Лимит объявлений на группу** | **Не более `3` неархивных** | Считаются `DRAFT`, `MODERATION`, `ACCEPTED`, `SUSPENDED`, `OFF` | 4-е объявление вызывает ошибку `7001`; для ротации старое нужно отправить в `Ads.archive` |

### Принцип комбинаторной когерентности `Titles × Texts`
Поскольку алгоритм комбинирует **любой** элемент из `Titles` с **любым** элементом из `Texts`:
1. Запрещено дробить одно предложение между заголовком №1 и заголовком №2.
2. Каждый заголовок обязан быть грамматически завершённым и не дублировать по смыслу соседние:
   - `Title 1`: точное вхождение маркерного запроса кластера (`Ремонт турбин в Москве за 1 день`);
   - `Title 2`: оцифрованная выгода / цена (`От 8 500 ₽ с гарантией 24 месяца`);
   - `Title 3`: УТП / снятие главного возражения (`Оригинальные картриджи BorgWarner на складе`);
   - `Title 4..7`: альтернативные формулировки под смежные интенты внутри кластера.
3. **Копирайтинг-фильтр `Ogilvy + Bly + Sugarman` для слотов `56 / 81` символов**:
   - *Ogilvy (фактическая плотность заголовка)*: в `Titles` запрещены абстрактные штампы («высокое качество», «индивидуальный подход») — каждый слот несёт проверяемую цифру, срок, гео или порог цены;
   - *Bly (`Feature -> Benefit`)*: в `Texts` любая техническая деталь переводится в выгоду покупателя («Склад запчастей в цеху — заберёте авто за 4 часа без простоя»); для B2B разделять выгоду `payer` (окупаемость, НДС, договор) и `user` (запуск без ручной рутины);
   - *Sugarman (мостик любопытства к первому экрану)*: завершать `Texts` конкретным микрошагом («Проверьте смету онлайн за 1 минуту»), бесшовно продолжающимся в первом предложении посадочной страницы (`Message Match`).
4. Любая правка `Titles` или `Texts` после прохождения модерации сбрасывает статус объявления из `ACCEPTED` обратно в `MODERATION`, обнуляя накопленный краткосрочный CTR комбинации.

## 4. Автотаргетинг на Поиске: категории, API-асимметрия и защита бюджета

На поисковых группах автотаргетинг обязателен на уровне платформы и представлен системной фразой `---autotargeting`, которая автоматически создаётся Яндексом внутри каждой поисковой группы.

### 4.1. Пять категорий автотаргетинга

| Категория API | Название в UI | Что подбирает алгоритм | Рекомендация для старта BOFU / лидогенерации |
|---|---|---|---|
| `EXACT` | Целевые запросы | Прямые синонимы и переформулировки продукта с явным коммерческим намерением | **`YES` (оставить включённой)** |
| `ALTERNATIVE` | Альтернативные запросы | Запросы по товарам-заменителям | `NO` на старте; включать только при исчерпании прямого спроса |
| `COMPETITOR` | Запросы с упоминанием конкурентов | Брендовые запросы прямых конкурентов | `NO` в основной кампании (выносить в отдельную конкурентную кампанию с адаптированным оффером) |
| `BROADER` | Широкие запросы | Информационные, верхнеуровневые и околоцелевые запросы | **`NO`** (главный источник нецелевого слива бюджета) |
| `ACCESSORY` | Сопутствующие запросы | Смежные товары и услуги | **`NO`** |

> **Жёсткое ограничение API (ошибка `5005`)**: запрещено выключать все 5 категорий одновременно (`Запрещено выключать все категории в автотаргетинге`). Минимум одна категория (как правило, `EXACT`) обязана оставаться `YES`.

### 4.2. Асимметрия чтения и записи автотаргетинга в API
1. **Запрет передачи в `AdGroups.add/update`**: передача `TextAdGroupAutoTargeting` или `AutoTargeting` в теле группы вызывает ошибку `8000` (если не используется специализированный инструмент `yandex_direct_update_adgroup_autotargeting`).
2. **Чтение через `Keywords.get`**: фильтрация по `AdGroupIds` с `FieldNames: ["Id", "Keyword", "AutotargetingCategories"]` возвращает строку `Keyword == "---autotargeting"`, где категории обёрнуты в объект `{ "Items": [{ "Category": "EXACT", "Value": "YES" }, ...] }`.
3. **Запись через `Keywords.update`**: при обновлении обёртка `Items` **не передаётся** — отправляется плоский массив:
```json
{
  "method": "update",
  "params": {
    "Keywords": [{
      "Id": 987654321,
      "AutotargetingCategories": [
        { "Category": "BROADER", "Value": "NO" },
        { "Category": "ACCESSORY", "Value": "NO" },
        { "Category": "ALTERNATIVE", "Value": "NO" },
        { "Category": "COMPETITOR", "Value": "NO" }
      ]
    }]
  }
}
```
4. **Контроль ставки автотаргетинга на ручных стратегиях**: при ручном управлении ставками системной фразе `---autotargeting` выставляется минимальная или умеренная ставка через `KeywordBids.set`, а в отчёте `SEARCH_QUERY_PERFORMANCE_REPORT` фразы из `---autotargeting` отделяются по полю `CriteriaType == "AUTOTARGETING"`.

## 5. Декларативный деплой через YAML-бандл `ohmy-seo`

Для воспроизводимого создания структуры `Campaign + AdGroups + Keywords + ResponsiveAds + Sitelinks` без ручных ошибок в последовательности вызовов используется инструмент `yandex_direct_upload_campaign_bundle` (либо `yandex_direct_upload_from_yaml` с обязательным прогоном `dry_run: true` перед живой мутацией).

```yaml
campaign:
  name: "SRC | Москва | Ремонт турбин | BOFU ЕПК"
  start_date: "2026-11-15"
  counter_ids: [94817263]
  attribution_model: "LAST_YANDEX_DIRECT_CLICK"
  bidding_strategy:
    search:
      type: "WB_MAXIMUM_CONVERSION_RATE"
      weekly_spend_limit_rub: 35000
      bid_ceiling_rub: 250
      goal_id: 301928374
    network:
      type: "SERVING_OFF"
  negative_keywords:
    - "своими руками"
    - "видео"
    - "форум"
    - "бу"
    - "разборка"
  tracking_params: "utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}"

ad_groups:
  - name: "ремонт турбин дизельных двигателей"
    region_ids: [213, 1]
    autotargeting:
      exact: true
      alternative: false
      competitor: false
      broader: false
      accessory: false
    keywords:
      - "ремонт турбин дизельных двигателей"
      - "ремонт дизельной турбины цена"
      - "\"ремонт турбины дизеля москва\""
    ads:
      - titles:
          - "Ремонт дизельных турбин в Москве за 4 часа"
          - "Диагностика 0 ₽ — гарантия 24 месяца по договору"
          - "Ремонт турбин от 8 500 ₽ со своим складом запчастей"
          - "Восстановление заводской геометрии на стенде CIMAT"
        texts:
          - "Снятие и установка в день обращения. Оригинальные картриджи в наличии. Звоните!"
          - "Бесплатная дефектовка при вас за 30 минут. Работаем с легковыми и коммерческими авто."
        href: "https://example.ru/remont-dizelnyh-turbin"
        display_url_path: "remont-turbin"
```

### Протокол безопасной выгрузки в прод
1. Проверить валюту кабинета (`Dictionaries.get{"DictionaryNames": ["Currencies"]}`) и доступный баланс (`yandex_direct_account_balance`).
2. Выполнить сухой прогон валидации лимитов слов (`<=22` / `<=23`), символов (`<=56` / `<=81`), синтаксиса минус-слов и UTM-параметров.
3. Создавать новые кампании в безопасном состоянии (`Status=DRAFT` / `State=OFF` или `SUSPENDED`), привязывать счётчик Метрики и `PriorityGoals`, проверять разметку ОРД (`erid`) и только после прохождения пре-лонч чек-листа отправлять на модерацию (`yandex_direct_moderate_ads`) и активировать показ.

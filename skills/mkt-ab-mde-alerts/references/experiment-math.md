## 1. Асимптотическая формула размера выборки, ошибки I/II рода и MDE

Любой эксперимент обязан фиксировать **до запуска** четыре параметра дизайна (блокировка в `active_locks.json`):
1. **$\alpha$ (уровень значимости / ошибка I рода, False Positive Rate)** — вероятность ложно обнаружить эффект там, где его нет ($H_0$ верна). Стандарт: $\alpha = 0.05$ (для критических изменений с высоким риском деградации выручки $\alpha = 0.01$).
2. **$\beta$ (ошибка II рода, False Negative Rate)** и **мощность $1 - \beta$ (Power / Sensitivity)** — вероятность обнаружить реальный эффект величины не ниже $\varepsilon = \text{MDE}$, если альтернатива $H_1$ верна. Стандарт: $\beta = 0.20 \Rightarrow \text{Power} = 80\%$ (для ключевых продуктовых релизов $\beta = 0.10 \Rightarrow \text{Power} = 90\%$).
3. **$\sigma_X^2, \sigma_Y^2$** — дисперсии целевой метрики в контрольной и тестовой группах, оценённые на предэкспериментальных исторических данных за аналогичное по длине окно (`7` или `14` дней, кратно полной неделе!).
4. **$\varepsilon = \text{MDE}$ (Minimum Detectable Effect)** — минимальный экономически осмысленный эффект (в абсолютных единицах $\varepsilon_{\text{abs}}$ или относительных $\varepsilon_{\text{rel}} = \varepsilon_{\text{abs}} / \mu_0$), ради которого оправдана раскатка фичи или смена оффера.

### 1.1. Классическая формула для непрерывных метрик и конверсий (двусторонняя альтернатива)
Для равного сплита $50/50$ ($n = n_A = n_B$ наблюдений **в каждой группе**):

$$n = \left\lceil \frac{\left(\Phi^{-1}(1 - \alpha/2) + \Phi^{-1}(1 - \beta)\right)^2 \cdot (\sigma_X^2 + \sigma_Y^2)}{\varepsilon_{\text{abs}}^2} \right\rceil$$

Для бинарной конверсии с базовой долей $p_0$ и ожидаемой конверсией в тесте $p_1 = p_0 + \varepsilon_{\text{abs}}$ ($\sigma_X^2 = p_0(1 - p_0)$, $\sigma_Y^2 = p_1(1 - p_1)$):

$$n = \left\lceil \frac{\left(\Phi^{-1}(1 - \alpha/2) + \Phi^{-1}(1 - \beta)\right)^2 \cdot \left(p_0(1 - p_0) + p_1(1 - p_1)\right)}{(p_1 - p_0)^2} \right\rceil$$

При неравном сплите $n_B = k \cdot n_A$ (например, безопасная выкатка на $20\%$ трафика соответствует $k = 0.25$):

$$n_A = \left\lceil \frac{(z_{1-\alpha/2} + z_{1-\beta})^2 \cdot \sigma^2 \cdot (1 + 1/k)}{\varepsilon_{\text{abs}}^2} \right\rceil, \qquad n_B = \lceil k \cdot n_A \rceil$$

> **Следствие для неравных сплитов**: сплит `90/10` ($k = 1/9$) увеличивает суммарно необходимый трафик эксперимента в $\frac{(1+9)(1+1/9)}{4} = \mathbf{2.78\text{ раза}}$ по сравнению со сплитом `50/50`! Максимальная статистическая мощность при фиксированном бюджете трафика всегда достигается на сплите **`50/50`**.

### 1.2. Эталонная реализация калькулятора выборки и обратного расчёта MDE (Python)
```python
import math
from scipy.stats import norm

def compute_sample_size_abs(epsilon: float, std1: float, std2: float,
                            alpha: float = 0.05, beta: float = 0.20) -> int:
    z_alpha = norm.ppf(1.0 - alpha / 2.0)
    z_beta = norm.ppf(1.0 - beta)
    return math.ceil(((z_alpha + z_beta) ** 2) * (std1 ** 2 + std2 ** 2) / (epsilon ** 2))

def compute_mde_abs(n_per_group: int, std1: float, std2: float,
                    alpha: float = 0.05, beta: float = 0.20) -> float:
    z_alpha = norm.ppf(1.0 - alpha / 2.0)
    z_beta = norm.ppf(1.0 - beta)
    return (z_alpha + z_beta) * math.sqrt((std1 ** 2 + std2 ** 2) / n_per_group)
```

### 1.3. Запрет «подглядывания» (`Peeking Problem`) и множественных сравнений
Ежедневная проверка `p-value < 0.05` с остановкой теста в первый день, когда кривая пробила порог, разгоняет реальную ошибку I рода с `5%` до **`25–35%`**.
- **Правило `Sample Size Lock`**: длительность теста (кратно полным неделям: `7`, `14`, `21` день для закрытия внутринедельной сезонности) и целевой `n_per_group` записываются в `active_locks.json` до старта. До набора `100%` выборки допустимы только **защитные проверки на поломку (`Guardrail Crash` с жёстким $\alpha_{\text{guard}} = 0.001$)** и проверка SRM.
- При одновременном сравнении $m$ тестовых групп против контроля (или $m$ равноправных целевых метрик) применяется поправка **Холма — Бонферрони**: упорядоченные $p_{(1)} \le p_{(2)} \le \dots \le p_{(m)}$ сравниваются с порогами $\frac{\alpha}{m}, \frac{\alpha}{m-1}, \dots, \alpha$.

## 2. Ограничения калькуляторов и метод Монте-Карло (Синтетические A/A и A/B)

Классическая формула опирается на центральную предельную теорему и однородность наблюдений. На реальных продуктовых и рекламных данных (просмотры постов, выручка на пользователя `ARPU`, число сессий) распределения имеют **тяжёлый правый хвост (логнормальная асимметрия)** и высокую долю нулей:
- В эталонном эксперименте при умеренном разбросе пользовательского CTR ($\sigma = 0.096$, базовый $\text{CTR} = 0.21$, желаемый сдвиг $+0.01$ или $+5\%$) формула даёт $n = 1\,447$ пользователей на группу.
- Однако при реалистичном логнормальном распределении просмотров ($\text{views} \sim |\lfloor e^{\mathcal{N}(1.0,\, 1.5^2)} \rfloor + 1|$, где медиана близка к 3 просмотрам, а 99-й перцентиль достигает `90` просмотров) стандартное отклонение пользовательских долей скачет до $\sigma \approx 0.278$, а требуемый размер выборки возрастает в **`8.4 раза`** — до **`12 132` пользователей на группу**!

### Алгоритм оценки `Sample Size` и валидации критерия методом Монте-Карло
1. **Выгрузка эмпирического распределения из БД (ClickHouse / BigQuery / Postgres)** за предшествующие 7–14 дней без активных аномалий (`views_distr`, `ctr_distr` через `scipy.stats.rv_discrete`).
2. **Синтетический A/A-тест ($N_{\text{sim}} = 2\,000\text{–}10\,000$ итераций без добавления эффекта)**:
   - Сэмплировать с возвращением две группы размера $n$ из одного исторического пула.
   - Посчитать массив `p_values_aa`. Критерий корректен тогда и только тогда, когда:
     - распределение `p_values_aa` равномерно на $[0, 1]$ (`scipy.stats.kstest(p_values_aa, 'uniform').pvalue > 0.05`);
     - эмпирический $\text{FPR} = \frac{1}{N_{\text{sim}}} \sum \mathbb{I}(p_i \le \alpha)$ попадает в доверительный интервал Уилсона вокруг $\alpha$ (для $\alpha = 0.05$ и $N_{\text{sim}} = 2000$: коридор `[0.040, 0.060]`).
3. **Синтетический A/B-тест (подбор минимального $n$ под заданную мощность $1 - \beta$)**:
   - Моделировать ожидаемый эффект (аддитивный сдвиг, мультипликативный `ctr_A = np.clip(ctr_B * (1 + mde_rel), 0, 1)` с розыгрышем кликов `stats.binom.rvs(views, ctr)` либо гетерогенный эффект через Бета-распределение).
   - Бинарным поиском по сетке $n$ найти минимальное число пользователей, при котором доля $\mathbb{I}(p_i \le \alpha)$ достигает `>= 0.80`.

## 3. Ratio-метрики и снижение дисперсии: Бакетизация, Линеаризация и CUPED

### 3.1. Почему нельзя применять наивный `ttest_ind` к показовым / кликовым строкам
В ratio-метриках вида $\text{CTR} = \frac{\sum \text{Clicks}_u}{\sum \text{Views}_u}$, $\text{CPC} = \frac{\sum \text{Spend}}{\sum \text{Clicks}}$ или $\text{AOV} = \frac{\sum \text{Revenue}_u}{\sum \text{Orders}_u}$ единицей рандомизации является **пользователь $u$**, но одно наблюдение события зависит от других событий того же пользователя. Пособытийный t-тест грубо занижает дисперсию и даёт ложные пробои ($\text{FPR} \gg 0.05$), а усреднение пользовательских отношений $\frac{1}{n}\sum \frac{X_u}{Y_u}$ искажает бизнес-метрику (пользователь с 1 просмотром и 1 кликом получает тот же вес, что и пользователь со 100 просмотрами).

Для корректной проверки ratio-метрик применяются **бакетное преобразование** или **линеаризация**.

### 3.2. Взвешенное бакетное преобразование (`Bucketization`)
Все пользователи каждой группы случайно (по хэшу `user_id`) делятся на $B$ равных бакетов (стандарт $B = 100$; при больших выборках $B = 200\text{–}1000$). Внутри каждого бакета $b \in \{1, \dots, B\}$ вычисляется истинная агрегированная ratio-метрика:

$$R_{g, b} = \frac{\sum_{u \in \text{bucket}(g, b)} X_u}{\sum_{u \in \text{bucket}(g, b)} Y_u} = \frac{\sum_{u \in \text{bucket}(g, b)} \text{CTR}_u \cdot \text{Views}_u}{\sum_{u \in \text{bucket}(g, b)} \text{Views}_u}$$

По ЦПТ распределения бакетных агрегатов $R_{A, 1..B}$ и $R_{B, 1..B}$ быстро сходятся к нормальным даже при скошенных исходных данных, после чего к двум векторам длины $B = 100$ применяется стандартный двусторонний t-тест Уэлча (`ttest_ind(..., equal_var=False)`), либо для оценки сдвига медианы — расчёт бакетных медиан + критерий Манна — Уитни. На скошенных логнормальных просмотрах взвешенная бакетизация заметно опережает наивный пользовательский t-тест по скорости выхода на мощность `80%`.

### 3.3. Линеаризация отношения (`Ratio Linearization`)
Линеаризация переводит групповую ratio-метрику обратно на уровень **отдельного пользователя $u$**, сохраняя математическое ожидание разницы с точностью до $O(1/n)$:

$$L_u = X_u - \kappa \cdot Y_u, \qquad \text{где } \kappa = \frac{\sum_{i \in \text{Control}} X_i}{\sum_{i \in \text{Control}} Y_i} = R_{\text{Control}}$$

- Например, для $\text{CTR}$: $L_u = \text{Clicks}_u - \text{CTR}_{\text{control}} \cdot \text{Views}_u$.
- Разность средних $\bar{L}_{\text{Test}} - \bar{L}_{\text{Control}}$ имеет тот же знак и статистическую значимость, что и разность глобальных отношений $R_{\text{Test}} - R_{\text{Control}}$, но позволяет считать честный попользовательский t-тест и напрямую комбинировать результат с **CUPED**!

### 3.4. Снижение дисперсии методом CUPED (`Controlled-experiment Using Pre-Experiment Data`)
Если для каждого пользователя $u$ известна ковариата $X_u$, собранная **строго до попадания пользователя в эксперимент** (например, выручка или число генераций за 14 дней до теста), строится скорректированная метрика с тем же математическим ожиданием эффекта ($\mathbb{E}[\bar{Y}_T^{\text{CUPED}} - \bar{Y}_C^{\text{CUPED}}] = \mathbb{E}[\bar{Y}_T - \bar{Y}_C]$, так как рандомизация гарантирует $\mathbb{E}[\bar{X}_T] = \mathbb{E}[\bar{X}_C]$):

$$Y_u^{\text{CUPED}} = Y_u - \theta \cdot (X_u - \bar{X}_{\text{pooled}}), \qquad \theta = \frac{\text{Cov}(Y, X)}{\text{Var}(X)}$$

Где $\theta$ и $\bar{X}_{\text{pooled}}$ вычисляются на объединённой выборке `Control ∪ Test` без подглядывания в метку группы. Итоговая дисперсия сжимается пропорционально квадрату коэффициента корреляции Пирсона $\rho_{XY}$:

$$\text{Var}(Y^{\text{CUPED}}) = \text{Var}(Y) \cdot (1 - \rho_{XY}^2) \implies n_{\text{CUPED}} = n_{\text{raw}} \cdot (1 - \rho_{XY}^2)$$

- При типичной автокорреляции пользовательской активности $\rho_{XY} = 0.60$ необходимый размер выборки сокращается на **`36%`**, а при $\rho_{XY} = 0.80$ — на **`64%`** (эксперимент идёт 1 неделю вместо 3 недель!).
- Для новых пользователей с холодным платным кликом ($X_u$ до теста отсутствует) полагают $X_u = 0$ либо используют предэкспериментальные поведенческие признаки первой секунды (гео, платформа `iOS/Android`, источник клика), строго не зависящие от варианта `A/B`.

## 4. Детерминированное хэш-сплитование и проверка SRM (`Sample Ratio Mismatch`)

### 4.1. Криптографически равномерный бакетинг с солью (`MD5 / SipHash + Salt`)
Разбиение пользователей по чётности `user_id % 2` или по времени прихода категорически запрещено из-за корреляции автоинкрементных ID с когортами и источниками трафика. Сплитование выполняется детерминированным хэшированием склейки идентификатора с уникальной **солью эксперимента (`salt`)**:

- **ClickHouse SQL**:
  ```sql
  sipHash64(concat(toString(user_id), '_exp_checkout_v2_2026_11')) % 100 AS bucket_id
  -- bucket_id IN (0..49) -> Control (A), bucket_id IN (50..99) -> Treatment (B)
  ```
- **Python (`hashlib.md5`)**:
  ```python
  import hashlib

  def assign_bucket(user_id: str | int, salt: str, n_buckets: int = 100) -> int:
      digest = hashlib.md5(f"{user_id}:{salt}".encode("utf-8")).hexdigest()
      return int(digest[:15], 16) % n_buckets
  ```

Смена `salt` между независимыми экспериментами делает их разбиения взаимно ортогональными (коэффициент корреляции попадания в тест двух разных фич равен $0$). Для взаимоисключающих тестов одного и того же экрана используется **единый слой (`Layer`) с общей солью**: например, бакеты `0..24` — Тест 1 (контроль), `25..49` — Тест 1 (вариант), `50..74` — Тест 2 (контроль), `75..99` — Тест 2 (вариант).

### 4.2. Обязательный гейт `SRM` (`Sample Ratio Mismatch`) перед расчётом `p-value`
Если дизайн предполагал сплит `50/50`, а фактически в группу `A` попало `10 420` пользователей, а в группу `B` — `9 580`, эксперимент **сломан технически** (редирект варианта `B` падает на старых Safari, тяжёлый бандл отваливается до отправки аналитического хита, бот-трафик неравномерно отфильтрован или сломан кэш CDN).

Перед интерпретацией продуктовых метрик запускается тест согласия $\chi^2$ Пирсона с жёстким порогом $\alpha_{\text{SRM}} = 0.001$:

$$\chi^2 = \sum_{g \in \{A, B\}} \frac{(O_g - E_g)^2}{E_g}, \qquad p_{\text{SRM}} = 1 - F_{\chi^2_1}(\chi^2)$$

- Если **`p_SRM < 0.001`** — выводится критический блокер `SRM_DETECTED`: расчёт продуктового аплифта блокируется как недействительный (выжившие в группе `B` — смещённая подвыборка!), запускается техническая форензика потерь хитов в разрезе `OS × Browser × Country × Entry URL`.
